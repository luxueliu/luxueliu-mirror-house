# 为什么第三关不是 quine

> 这一页解释一个删掉的设计。它不影响玩，只影响你理解这座镜屋的边界。

## 原本想做的东西

最早的三关是「数、字、码」：自描述数、回文、quine——一个运行后打印自己源代码的程序。三条都验过：

- Python 版两行，41 字节；
- JavaScript 版一行，54 字节；
- 把输出当新程序再跑一遍，还是原文。

quine 是自指最漂亮的样子：程序把自己完整地含在身体里，不读文件，不照抄。

## 为什么删掉

因为「验 quine」意味着**运行提交者交上来的程序**。

哪怕加超时、限制工作目录、清环境变量，Python 代码仍然可以删文件、读环境、连网络。一个公开小游戏，让任何 clone 它的人跑任何 agent 交上来的代码，这个默认值不对。做沙箱当然可以，但那就不是「单文件、零依赖、双击就玩」了。

这不是技术做不到，是**不值得**：为了一个关卡，把整个仓库的安全性押上去。

## 换成了什么

第三关换成「互相画像」：找两个十位数 A、B，A 的十格描述是 B，B 的十格描述是 A。

它和 quine 是同一种自指——一个东西通过描述另一个东西来描述自己——但判卷只需要算术和字符串，不需要执行任何东西。而且它有一个 quine 没有的好处：答案不是唯一的自我，而是一对**互相描述、谁也不等于自己**的数。

## 边界

- 第二关也只验形式：回文对不对、长度对不对、用字对不对。意思好不好，机器判不了。
- 这个仓库的默认值是：**能安全验的才验，不能安全验的就不做**。少一关，换一个可以放心公开的仓库。
